### Skill configuration

All skills call the AssemblyImpact actions through the destination variable `assemblyImpactBackend`.

**Quoted OData strings.** The Actions spec accepts query strings only as quoted OData literals, with the pattern
`^(null|'…')$`. Every free-text input is therefore wrapped in a formula:

```
ConcatenateStrings(["'", <input>, "'"], "")
```

An empty input becomes `''`. The backend treats `''` as "no filter": `unquote('')` is falsy, see
`srv/engineering-review.js`.

**Engineering Case Lookup**
- Inputs: `caseNumber`, `assemblyCode`, `caseStatus`. All three are now mapped through the quoting formula; before,
  they were mapped raw.
- Output: *Cases*, bound to the action result.
- Default branch: an error message.

**Explain Case Impact**
- Input: Case Number (required).
- Steps: *Look up cases* (quoted `caseNumber`), then *Get an engineering impact run* with
  `ID = ConcatenateStrings(Map(value, latestRun_ID), "")`.
- Branches: 4XX → "No impact run available for this case". Default → "Impact could not be retrieved".
- Outputs, typed as in the API:

  | Output | Type | Source |
  |---|---|---|
  | `runStatus` | String | `result.status` |
  | `costDeltaTotal` | Number | `StringToNumber(ConcatenateStrings([result.costDeltaTotal], ""))` |
  | `currency` | String | `result.currency` |
  | `materialsShort` | Number | `result.materialsShort` |
  | `materialsUnknown` | Number | `result.materialsUnknown` |
  | `instructionFindings` | Number | `result.instructionFindings` |

  `costDeltaTotal` stays a **Number**. The API declares decimals as `anyOf(number, string)`, which Joule cannot bind to
  a Number output directly. Two direct routes were rejected:
  - a direct binding, and the output type "Any", both give a mapping type mismatch;
  - `StringToNumber(costDeltaTotal)` fails because the input is not typed as a string.

  The formula above normalises either representation to a number. It does not change the value. The currency stays
  a separate String output.

**Review Decision History** (new)
- Input: Case Number (required).
- Steps: *Look up cases* (quoted), then *Get decisions* with `ID = ConcatenateStrings(Map(value, ID), "")`.
- Branches: Look-up Default → "Case could not be looked up". Get-decisions Default → "Decision history could not be
  retrieved".
- Output: *Decisions*, typed `get_getReviewCasesIdDecisions_200_output_schema` and bound to the action result.
- The skill is read-only and invents no decisions.

**Run Engineering Impact** (new)
- Input: Case Number (required).
- Steps: *Look up cases* (quoted), then **Send Confirmation Request**.
  - Title: "Run a new engineering impact calculation?"
  - Buttons: *Run impact* / *Cancel*.
  - Text: states that the ImpactRunner role is required.
- Only the **Confirm** branch calls *Run the engineering impact calculation*: `POST
  /ReviewCases({ID})/EngineeringReview.runImpact`, with ID = `Map(value, ID)`. `asOfDate` is left empty, so the server
  default applies.
- 4XX → "Impact run was refused (missing ImpactRunner role, plant not authorized, or case not found). Nothing was
  changed."
- *Cancel* calls nothing.
- Output: *Impact Run*, typed `post_RunEngineeringImpact_200_output_schema` and bound to the POST result.
- **Authorization is enforced by the server, not by Joule.** `srv/engineering-review.cds` grants `runImpact` only to
  `ChangeAnalyst` and `ImpactRunner`. `test/p1-actions-contract.test.js` asserts that a ChangeViewer gets **403** and
  that a case in another plant gives **404**. All 9 contract tests passed locally on 2026-11-10.
